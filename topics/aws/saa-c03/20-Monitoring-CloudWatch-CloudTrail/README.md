# Module 14 — Monitoring: CloudWatch, CloudTrail, Config and Related Services

## Overview of the AWS Monitoring Stack

```
Observability = Metrics + Logs + Traces + Events

CloudWatch    → Metrics, Logs, Alarms, Dashboards, Anomaly Detection
CloudTrail    → API call auditing (who did what, when, from where)
AWS Config    → Resource configuration (what is configured how)
X-Ray         → Distributed tracing (latency and bottlenecks in microservices)
Systems Manager → Instance management and operational parameters
```

---

## Amazon CloudWatch

### Metrics

- Point-in-time data with namespace, name, and dimensions
- **EC2 default**: CPUUtilization, NetworkIn/Out, StatusCheckFailed (**does not include memory/disk**)
- **Custom metrics**: via CloudWatch Agent or `PutMetricData` API
- **Default granularity**: 1 minute (basic) or 5 minutes (EC2 without detailed monitoring)
- **High Resolution Metrics**: up to 1 second (standard = 1 min; high-resolution = 1s, 5s, 10s, 30s)
- Retention: 3h (1s), 15 days (1min), 63 days (5min), 15 months (1h)

### CloudWatch Alarms

| State | Description |
|---|---|
| OK | Metric within threshold |
| ALARM | Metric exceeded threshold |
| INSUFFICIENT_DATA | Insufficient data to evaluate |

**Alarm Actions:**
- EC2 Actions (stop, terminate, reboot, recover)
- Auto Scaling Actions (scale out/in)
- SNS Notification (email, webhook, Lambda, SQS)
- Systems Manager OpsItem

**Composite Alarms**: an alarm that combines multiple alarms with logical AND/OR → avoids "alarm storms"

### CloudWatch Logs

```
Log Group (e.g., /aws/lambda/my-function)
  └── Log Streams (generated by each execution environment or instance)
        └── Log Events (individual log lines + timestamp)
```

**Retention**: configurable per group (1 day to Never Expire); logs expire automatically if configured

**Insights**: SQL-like queries on logs; supports pattern/parse/stats/sort/dedup
```
fields @timestamp, @message
| filter @message like /ERROR/
| stats count() by bin(5m)
```

**CloudWatch Agent**: collects OS metrics (memory, disk, processes) and custom file logs; uses `config.json` or SSM Parameter Store

**Subscriptions**: real-time delivery of logs to Lambda, Kinesis Streams, Kinesis Firehose, OpenSearch

### CloudWatch Contributor Insights

Analyzes logs to identify "top contributors" to errors/latency (e.g., top 10 URLs with most errors, top IPs)

### CloudWatch Anomaly Detection

Creates a band of expected values for a metric using ML; alarms when the value falls outside the band

## AWS CloudTrail

API call auditing across all AWS services:

### Event Types

| Type | Examples | Default |
|---|---|---|
| **Management Events** | CreateBucket, TerminateInstances, CreateUser | Enabled by default |
| **Data Events** | S3 GetObject/PutObject, Lambda Invoke, DynamoDB GetItem | Disabled (high volume) |
| **Insights Events** | Unusual API activity (ML-based) | Enabled separately |

### Trails

- **Single-region**: records events only in the region where created
- **All-regions**: recommended for organizations; replicates events to a central S3 bucket
- **Multi-account via Organizations**: one trail covering the entire org

### CloudTrail Lake

- Aggregation and querying of CloudTrail events in SQL (EventBridge Schema)
- Configurable retention up to 7 years
- Alternative to S3 + Athena delivery

## AWS Config

Continuous recording of resource configuration and compliance evaluation:

**Config Recording**: snapshot and configuration history of resources (what changed, when, who changed)

**Config Rules**: evaluates resource compliance:
| Type | Description |
|---|---|
| **AWS Managed Rules** | 100+ ready-made rules (e.g., s3-bucket-public-read-prohibited, required-tags) |
| **Custom Rules** | Lambda function that evaluates the configuration |
| **Detective Rules** | Evaluates current configuration (when change happens) |
| **Proactive Rules** | Evaluates **before** creating a resource via CloudFormation (prevents creating non-compliant resources) |

**Remediation**: Config + SSM Automation (automatically fixes non-compliant resources)

**Aggregator**: aggregates Config data from multiple regions/accounts into a single central account

## AWS X-Ray

Distributed tracing for applications:

```
Request trace = set of segments from an end-to-end request
  └── Segment: operation in a single service/resource
        └── Subsegment: operation within the segment (e.g., DynamoDB call)
              └── Annotations: indexed key-value (filterable)
              └── Metadata: non-indexed key-value (for debugging)
```

**Service Map**: graphical visualization of dependencies and latency between services

**X-Ray Daemon**: collects traces sent by the SDK and sends them to the X-Ray API (avoids each app calling the API directly)

**Native integrations**: Lambda, API Gateway, ALB, ECS, EC2 (with daemon), Elastic Beanstalk, Step Functions

## AWS Systems Manager (SSM)

### Session Manager
- SSH/RDP access without opening ports (no inbound security groups), without bastion, without key pairs
- Sessions recorded in S3/CloudWatch; audited via CloudTrail
- Requires SSM Agent on the host + IAM role `AmazonSSMManagedInstanceCore`

### Parameter Store
- Hierarchical configuration and secrets storage
- **/Standard**: free; up to 4KB per parameter; no rotation history
- **/Advanced**: paid; up to 8KB; TTL policies; Secrets Manager integration

| Type | Encryption | Cost |
|---|---|---|
| String | No | Free (Standard) |
| StringList | No | Free (Standard) |
| SecureString | AWS KMS | Free (Standard) + KMS costs |

### Patch Manager
- Defines Patch Baselines (which patches to approve/reject)
- Patch Groups: groups instances by tag for differentiated patching
- Maintenance Windows: schedules patches for maintenance windows

### Run Command
- Executes commands or scripts on instances without SSH access
- Uses SSM Documents (JSON/YAML that defines actions)

## AWS Trusted Advisor

Recommendations in 6 categories:
- **Cost Optimization**: idle/underutilized resources
- **Performance**: service limits, throughput
- **Security**: open security groups, root MFA, public bucket
- **Fault Tolerance**: backups, Multi-AZ, snapshots
- **Service Quotas**: usage near service limits
- **Operational Excellence** (Business/Enterprise Support)

**Developer** plan: only basic checks (Service Quotas + Security essentials)
**Business/Enterprise** plan: all checks + programmatic access via API

## Exam Tips

- CloudWatch does **not** collect EC2 RAM memory/disk usage by default → needs CloudWatch Agent
- CloudTrail **Management Events** enabled by default; **Data Events** are opt-in (cost extra)
- CloudTrail Insights: detects **unusual API activity** (e.g., spike in `TerminateInstances` calls)
- AWS Config Rule: evaluates **compliance** (does not block creation); to block, use **Service Control Policies** or **Config Proactive Rules with CloudFormation hooks**
- **X-Ray Sampling**: by default, 5% of requests are traced (configurable to reduce cost)
- Parameter Store vs Secrets Manager: Secrets Manager has **native automatic rotation** (RDS, Redshift, DocumentDB); Parameter Store has no native rotation
- SSM Session Manager: **zero SSH ports** — best security practice instead of bastion hosts
- CloudWatch Logs Insights supports queries like `fields @timestamp | filter level = "ERROR" | sort @timestamp desc | limit 20`
- Composite Alarms: combine multiple alarms to reduce unnecessary notifications
- config:// (AWS Config) = snapshot of **resources**; cloudtrail:// = snapshot of **API actions**
